# VibeLab 自主开发记录

## 起点与约束

- 工作目录包含本次会话此前的未提交修改；继续在其上增量开发，保留用户作品、配置与密钥。
- 导演级目前采用同步请求：服务端全部模型步骤完成后才保存项目，网页只显示临时等待状态；任何断线、超时或异常都可能导致用户无法找到结果。现有记录不足以证明具体一次失败的根因。
- 动画以受控 Canvas 组件为主；模型生成的代码不执行。参考样片的定制动画质量尚未达到。
- 不主动调用真实模型、图片、视频和配音接口；验证优先使用模拟与短片段。

## 已完成：分镜任务持久化

- `app/main.py`、`app/director.py`、`web/app.js`：新增后台分镜任务、真实阶段状态、页面刷新后继续追踪及失败信息；旗舰导演输出可用分镜后先写入工程，再运行动画优化。服务中断后保留基础分镜并标记为中断。
- 兼容原同步创建接口和离线示例；后台规划进行中禁止编辑或导出，以避免覆盖。
- 针对性验证：模拟动画阶段失败后基础分镜仍在、模拟服务重启后的中断识别，现有 12 项单元测试通过；前端 JavaScript 语法检查通过。
- 仍未验证真实硅基流动模型、浏览器实际长时间交互；规划任务注册表是单进程内存结构，当前仅支持现有单进程本地部署。

## 已完成：可执行场景与知识动效

- `app/scene_spec.py`、`app/scene_canvas.html`：增加受限关键帧事件（位移、缩放、透明度、缓动与附近节拍吸附）；输入经过范围和时间顺序校验，不执行模型代码。
- 新增 `growth` 复利曲线，使用明确的本金、每期百分比和期数计算；`app/director.py` 校验必要参数，工作台仅在选择该动画时显示相应字段。
- `app/agents/creative_brief.py` 描述可执行字段与边界。场景依然使用有限组件，不能声称支持任意视觉或独立对象的任意运动。
- `tests/test_canvas.cjs`：检查生日 23 个节点对应 253 条关系、天空散射图形、100 元以每期 10% 增长 3 期得到 133.1，以及关键帧对齐给定节拍；`tests/test_pipeline.py` 验证参数与事件校验。13 项 Python 测试及 JS 场景检查通过。
- 实际短镜头浏览器渲染尝试：本机发现 Chromium、Playwright 和 FFmpeg，但启动后长时间无输出，已主动中止；尚无实际新片段输出证据，原因尚未确定。不能据此判定用户的本地渲染环境损坏。

## 已完成：恢复、关系、节拍与字幕

- `app/main.py`、`app/director.py`、`web/app.js`：编剧完成后保存草稿和已返回的用量；当规划失败且没有分镜时，用户可主动重试并复用草稿；已保存分镜的工程不允许通过该重试入口覆盖。任务刷新后可继续追踪。
- `app/scene_spec.py`、`app/scene_canvas.html`：关系网络支持经过校验的自定义无向连线，默认仍支持完整两两关系。非法节点或连线会阻止该镜头渲染，而非悄悄替换为完整网络。
- `app/audio.py` 的节拍检测使用合成脉冲 WAV 进行了实际 FFmpeg 解码及瞬态点检查；Canvas 事件测试验证事件起止吸附到传入的节拍数组。没有对真实音乐的逐拍准确性或完整歌曲审片做结论。
- `app/render.py`、`app/browser_render.py`、`app/scene_canvas.html`：字幕分段按字符长度估时，画面与 SRT 采用相同时间分配；仍非语音强制对齐。浏览器绘制错误与外部素材加载错误不再混为一谈。
- `app/services/media_assets.py`：极速档中用户明确选取图片时使用可配置的 `image_fast`；其他档位使用 `image`，视频与配音仍按镜头选择和用户的配音选项调用。未自动发起真实模型请求。

- `app/director.py`、`app/agents/creative_brief.py`：单个工程的场景上限由 8 提升到 16；90 秒以上的目标建议规划 10–12 个不同职能的镜头。只是增加规划空间，不保证模型输出更高质量。
